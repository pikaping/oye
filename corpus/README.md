# Oye Corpus

A dataset of colloquial Spanish utterances for testing conversational agents.
The text of each entry is in Spanish; the documentation is in English.

## Format

Files in `corpus/data/` are JSONL (UTF-8, one JSON object per line). Each entry has:

| Field       | Description |
|-------------|-------------|
| `id`        | Unique id, `oye-` plus at least 4 digits. |
| `text`      | The utterance, in colloquial Spanish, anonymized. |
| `intent`    | What the speaker wants (e.g. `check_balance`). |
| `region`    | `es-ES`, `es-MX`, `es-AR`, `neutral`, ... |
| `features`  | Linguistic features from a closed set (`slang`, `ellipsis`, `typo`, ...). |
| `synthetic` | `true` if the phrase was generated rather than collected. Defaults to `false`. |

See [SCHEMA.md](SCHEMA.md) and [schema.json](schema.json) for the full definition.

## Loading

```python
from corpus import load_corpus

entries = load_corpus("corpus/data/oye-es-001.jsonl")
print(entries[0].text)
```

`load_corpus` validates every line and raises `CorpusError` with `<path>:<line>` on the first invalid one.

## Validating

Check corpus files for format errors and duplicates with:

```
python -m corpus.validate [--strict] [PATH ...]
```

Without paths it validates `corpus/data/`. Paths may be files or directories.
Every problem is printed as `file:line: code: message`, followed by a summary.
The validator reports all problems, never stops at the first one, and never modifies any text.

Exit codes:

- `0`: no errors.
- `1`: at least one error (or, with `--strict`, at least one warning).

Duplicates:

- **Exact duplicate** (error): the same `id` or exactly the same `text` appears more than once.
- **Near-duplicate** (warning): texts that differ but are equal once normalized
  (lowercase, no accents, no punctuation, collapsed spaces), e.g. `Cuanto cuesta?` and `cuánto cuesta`.

Warnings do not change the exit code unless you pass `--strict`, which treats them as errors.

This validator is the basis of the next milestone, a CI check. That workflow will be staged in `ci/`
and noted in `NOTES.md` for the author to move into place.
See [docs/corpus-ci.md](../docs/corpus-ci.md) for what it checks and how to run it locally.

## Contributing

1. Add entries to a file in `corpus/data/` (or a new `oye-es-NNN.jsonl`), with the next free `id`.
2. Fill in every field and pick `features` only from the closed set.
3. Run `pytest` and make sure it passes.

## Anonymization

Phrases must never contain real names, phone numbers, emails, addresses or any other personal data.
Replace or invent such details before contributing.

## Synthetic phrases

Any phrase written or generated by a model or by hand-crafting rather than collected from real speech
must be marked `"synthetic": true`. Only mark `false` for genuinely collected, anonymized phrases.
